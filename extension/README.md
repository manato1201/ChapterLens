# ChapterLens 拡張

YouTube の動画ページに、**話題の切り替えから作った目次(チャプター)**を重ねて表示する Chrome 拡張(Manifest V3)。
字幕があれば**拡張の中だけ**で処理する(何も送信しない)。字幕が無い動画・ライブでは、**この PC の中のエンジン**(127.0.0.1)だけに音声を渡す。
全体は [README](../README.md)、設計は [設計書](../ChapterLens_DESIGN.md)。

![拡張の中のメッセージの経路](../docs/diagrams/extension-messages.svg)

| 段階 | 内容 | 状態 |
|---|---|---|
| CH1 | 字幕から作る目次 | 実装済み |
| CH2b | 字幕が無い動画の、タブ音声から作る | 実装済み(本物の Chrome では未確認) |
| CH3b | 章の調整・少人数での共有・共有と管理ページ | 実装済み |
| CH4 | ダイジェストの自動シーク | 実装済み(人の判断との一致は未測定) |
| CH5 | ライブ(暫定 → 確定) | 実装済み(本物のライブは未確認) |

**まだ、実際の Chrome に拡張として読み込んでの動作確認はしていない**(下の「確認の範囲」)。

## できること

画面は、動画ページの右下の「目次」ボタン → パネル(3 つのタブ: 目次 / ダイジェスト / 共有)。

| 機能 | 使い方 | エンジン |
|---|---|---|
| **目次を作る** | 「目次」タブ →「目次を作る」。ページの文字起こしから、話題の切り替えを検出して章に分ける | 不要 |
| **粒度** | 自動 / 粗い / 標準 / 細かい(投稿者のチャプター数は 6〜70 とばらつくので、利用者が選ぶ) | 不要 |
| 章をクリックでシーク・現在の章を強調・進捗バーの黄色の目印 | — | 不要 |
| **概要欄用にコピー** | 「0:00 題名」の形(3 章以上・各 10 秒以上のときだけ) | 不要 |
| **章の調整** | 各章の「−5 / +5 / ×」と「いまの位置に章を足す」。**この PC のブラウザにだけ保存**し、次回その章立てで始まる。「自動に戻す」で戻せる。直した章がある間は粒度を変えられない(黙って捨てない)。最小の章は 5 秒 | 不要 |
| **ダイジェスト** | 「ダイジェスト」タブ。重要そうな区間を選び(既定は長さの 20%。10/20/30%)、オンにすると**区間の外を自動で飛ばして再生**(最後で自動的にオフ)。動画は切り出さない。チェックで外す・「いまの位置から 15 秒を足す」で足せ、調整すると**自動案との一致率**が出る | 不要 |
| **音声から作る** | 字幕が無い動画で、アイコン →「この動画の音声から作る」。30 秒ごとに結果が増える | **要** |
| **ライブ** | ライブ配信のタブで「音声から作る」。**暫定の章(「仮」)→確定**が増える(暫定は変化から約 9 秒・確定は約 27 秒)。ライブでは調整・ダイジェスト・共有は使えない | **要** |
| **共有** | 「共有」タブ。管理者が許可した範囲で、この動画の**章の境界の時刻だけ**を共有(題名は選んだときだけ・字幕/音声/動画は共有しない)。他の人の章立てを、進捗バーに紫で**重ねる**・「この章立てを使う」。いつでも取り下げられる | **要** |
| **共有と管理ページ** | アイコン →「共有と管理を開く」。自分のデータの削除。**管理者の token のときだけ**、利用者の追加(token は 1 度だけ表示)・停止/再開・token 再発行・削除・共有範囲・監査ログ。**権限はエンジンが確かめる** | **要** |

設定(粒度・調整)は `chrome.storage.local` に保存する(使えない環境でも動く)。

## 入れ方(開発版)

1. Chrome で `chrome://extensions` を開き、右上の「デベロッパー モード」をオンにする
2. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダ(`extension/`)を選ぶ
3. YouTube の動画を開き、右下の「目次」→「目次を作る」

## 音声から作る(CH2b)

字幕(文字起こし)が無い動画で使う。再生中のタブの音を取り込み、ローカルのエンジンで文字にして、同じ検出で章に分ける。

1. **エンジンを起動**(`engine/` で。初回は音声認識用の追加依存と、GPU が要る。詳しくは [engine/README.md](../engine/README.md))
   ```bash
   uv run --extra asr python -m chapterlens serve --allow-origin chrome-extension://egcgicajchobpecnggcblcbnoadlnfai
   ```
   `egcgicajchobpecnggcblcbnoadlnfai` は、この拡張の固定の ID(`manifest.json` の `key` から決まる。Chrome ウェブストアに出すときは `key` を外す)。token は `~/.chapterlens/token`(初回起動で作られる)
2. YouTube の動画ページを開き、**ツールバーの ChapterLens のアイコン**を押す → エンジンの URL(既定 `http://127.0.0.1:8787`)と token を入れ →「この動画の音声から作る」
3. 動画を再生する。**30 秒ごとに結果が増える**(目次パネルが自動で開く)。止めるには、もう一度アイコン →「停止」。動画を切り替えても止まる

仕組みと注意:

- **再生の速さでしか進まない**(1 時間の動画は 1 時間かかる)。2 倍速で見れば、2 倍速で進む。字幕のある動画は、これまでどおり「目次を作る」(すぐ終わる)
- 途中から見始めたときは、**聞いた範囲だけ**を章にする(最初の章は 0:00 から始まる表示になる)。シークで戻って聞き直した範囲は、新しい結果で置き換える
- 一時停止・シーク・倍速でも、字幕の時刻は動画の再生位置に直す(時計と再生位置の対応表 `TimeMap` で変換)
- 音は、取り込んでも利用者に聞こえるまま流す。**ファイルには保存しない**(メモリで処理し、エンジンも一時フォルダで処理して消す)
- 送り先は **`http://127.0.0.1:<ポート>` だけ**(別のホスト・https・パス付きは、送る前に拒否する)。エンジンは token と Origin の検査で、この拡張以外からの呼び出しを断る
- 認識の言語は、最初の 30 秒で決めて固定する(自動判定)。日本語・英語を popup で指定もできる
- エンジンの処理が追いつかないとき・無音のときは、その区間を飛ばす(無音は送らない)
- 認識がうまくいかない音(BGM が大きい・複数人の重なり)は、章の精度が下がる(下の「限界」)

## 権限と、外に出るもの

| 権限                                | 使う理由                                                                                           |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- |
| `storage`                           | 粒度・章の調整・ダイジェストの調整・エンジンの URL と token の保存(この PC のブラウザの中だけ)   |
| `tabCapture` + `activeTab`          | 再生中のタブの音を取り込む(利用者がアイコンを押したタブだけ)                                       |
| `offscreen`                         | 取り込んだ音を処理する画面を、見えない形で持つ(Manifest V3 の決まり)                               |
| `host_permissions: 127.0.0.1`       | この PC のエンジンへ音声を渡す                                                                     |
| content script: `youtube.com` だけ  | 目次の表示と、字幕(文字起こしパネル)の読み取り                                                     |

- **共有・ライブ・管理でエンジンを呼ぶのは、利用者が操作したときだけ**。通信は `background.js` が中継する(送り先は `127.0.0.1` だけ・許可リストの 13 経路だけ・この拡張の中からだけ・リダイレクトは辿らない・token は保存済みの設定から読む)。ライブでは、認識した字幕の本文をエンジンへ送る(インターネットには出ない)。共有で送るのは、境界の時刻(と、選んだときだけ題名)
- **字幕から作るとき(CH1)は、何も送信しない**。**音声から作るときだけ**、音声を `127.0.0.1` のエンジンへ渡す(インターネットには出ない。テストでソースを検査している: `fetch` は offscreen だけで、送る前に 127.0.0.1 かを必ず確かめる)
- 動画ファイル・字幕ファイルは取得しない。読むのは、**ページが見せている文字起こし**と、**利用者が再生している音**だけ(視聴と同じ範囲)
- token は `chrome.storage.local` に保存する(この拡張だけが読む。他の人に見せない)
- 文字は `textContent` だけで画面に入れる(HTML として解釈しない)

## 仕組み(薄く保つ)

| ファイル            | 役割                                                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/core.js`       | 検出器(topic-shift@2)の JavaScript 版・章の組み立て・書式。DOM なし。**Python 版と同じ境界を返す**                                                   |
| `src/transcript.js` | ソース・アダプタ。文字起こしパネルを開いて読む。**YouTube の画面の作りが変わると壊れるのは、ここのセレクタだけ**(壊れたら理由つきのエラーで知らせる) |
| `src/ui.js`         | 画面(Shadow DOM。3 つのタブ: 目次 / ダイジェスト / 共有。状態を持たず、渡された内容を描くだけ。ダークテーマに追従)                                  |
| `src/store.js`      | 動画ごとの調整(章・ダイジェスト)の保存。時刻だけ・新しい順に 100 本まで・壊れた値は読み飛ばす                                                      |
| `src/engine.js`     | エンジンの API を頼む口(共有・ライブ・管理)と、失敗の説明。ネットワークには触れない                                                                  |
| `src/admin.html` `src/admin.js` | 共有と管理のページ。2 度押しで実行する(削除・token 再発行)                                                                              |
| `src/content.js`    | 全体の制御。動画の切り替え(SPA)で前の結果を捨てる。音声の取り込みの結果を、動画の時刻に直して積む                                                    |
| `src/capture.js`    | 音声の取り込みの、ブラウザ API に触れない部分(16kHz へ・30 秒の区切り・WAV・時計↔再生位置・エンジンへの送信と失敗の扱い)。Node でテストできる            |
| `src/offscreen.js` `src/pcm-worklet.js` | タブの音を受け取り(AudioWorklet)、capture.js へ渡す。薄い配線だけ                                                                  |
| `src/background.js` | offscreen の作成・結果のタブへの中継・**エンジンの API の中継**(許可リスト・送り先の検査)                                                            |
| `src/popup.html` `src/popup.js` | アイコンを押したときの画面。開始・停止・エンジンの URL と token                                                                           |

## テスト

```bash
npm test                          # 146 件(Node の標準機能だけ。依存なし)
node tools/parity_real.mjs        # 実データ(ローカル)で Python 版と一致するか。先に engine で export_golden.py real
node tools/mock_server.mjs        # YouTube に似せたモックを http://localhost:8765/watch?v=mock で配信(画面の確認用)
node tools/e2e_audio.mjs <wav> <json> --url http://127.0.0.1:<port> --token <token> --origin chrome-extension://<ID>
                                  # 音声の取り込みの処理(16kHz 化→30 秒の区切り→HTTP→時刻変換→検出)を、実エンジンに通す
```

- **Python 版との一致**: 合成データ 5 ケース × 3 モード(`test/golden/golden.json`。engine の `tools/export_golden.py golden` で作る)で完全一致。**実データ 39 本 × 2 モード = 78 通りも完全一致**(ローカルで確認)。
- 速度: 39 本(1 本あたり字幕 200〜860 行)の検出が 1.7 秒。画面での実測は 6〜23ms。

## 限界

- **ダイジェストの区間は、字幕の言葉だけから決めた目安**で、人の「重要」との一致は未測定(調整の一致率が出るので、使いながら測れる)。音量・笑い声・映像は見ない。実際の長さは、予算(20%)より 2〜9 ポイント多くなる(中央値 25%)
- **ライブは、本物のライブ配信では未確認**(YouTube のライブの判定は `video.duration` が有限でないか `.ytp-live` の有無。画面の作りが違えば、ライブと判定されず、通常の取り込みになる)。字幕の認識の遅れが、そのまま「仮」「確定」の遅れに上乗せされる
- token は `chrome.storage.local` に平文で保存される(この拡張だけが読めるが、PC を使う他の人には見える)。設計書 S-B の「OS の資格情報ストア」には、まだなっていない

- **会話系(対談・ポッドキャスト)の精度は低い**(評価データでは、題材により F1 0.17〜0.24。基準の約 2 倍)。章は「候補」で、位置は数秒〜十数秒ずれる。題名は、その章の最初の字幕の冒頭(要約ではない)
- **音声から作る機能は、本物の Chrome・本物の動画で未確認**。合成音声(静かで明瞭)でしか精度を測っていない。日本語の合成音声では、認識の誤り(「糖分が絡めるかして」など)で 3 つ目の境界が 21 秒ずれた。BGM・複数人・雑音の入った本物の音での精度は未測定
- 音声から作るときは、見始めてから聞いた分だけが対象(後ろへシークして飛ばした区間は空のまま)
- 自動の文字起こしがある動画は、YouTube が既に章を持っていても、重ねて表示する
