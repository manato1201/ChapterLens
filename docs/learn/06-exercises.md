# 6. 演習

答えは 1 つではありません。**契約(何を保証するか)を先に書き、テストを先に書いて**から実装します。
[講義 第 14 回](../lecture/14-capstone.md) の演習(検出器を足す)の次の段階です。

## 演習 1: 章の題名を良くする(拡張 + Python)

**今**: 題名は、その章の最初の字幕の冒頭 24 文字。
**課題**: その章に**特徴的な語**(TF-IDF の重みが大きい語)を使った題名にする。

- 契約: 題名は 24 文字以内。字幕が空なら空文字。同じ入力で同じ題名(**決定的**)。
- 触る場所: `core.js::buildChapters`、Python 側に同等の関数(golden で一致を確かめる)。
- 評価: 人が見て、元の題名より良いか。**投稿者の題名との語の重なり**を、簡単な指標にしてもよい(測ってから採否を決める)。
- 落とし穴: 日本語の bigram は、そのままでは題名にならない(「機械」「械学」)。連続する bigram をつなぎ直す工夫が要る。

## 演習 2: ライブの「仮」を、見分けやすくする(拡張)

**今**: 暫定の章に「仮」の札が付く。
**課題**: 暫定の章が**確定した瞬間**を、利用者に気づかせる(例: 一度だけ強調する)。

- 契約: 確定した章は、位置が動かない(時刻は変化の始まりに付く)。強調は 3 秒で消える。
- 触る場所: `content.js::applyLiveMarkers`(前回の `tentative` と比べる)、`ui.js`。
- テスト: `features.test.mjs` に、「暫定 → 確定」の 2 回の応答を流し、強調の指示が**確定の回だけ**に出ることを確かめる。
- 落とし穴: 同じ応答が 2 回来ても、強調を**重ねて出さない**(冪等)。

## 演習 3: 共有に「コメント」を足す(エンジン + 拡張)

**課題**: 共有する章立てに、**短いメモ**(100 文字まで)を付けられるようにする。

- 契約: メモは、共有する利用者が**明示して**書いたときだけ送る。字幕のコピーが紛れ込まないよう、**上限**を設ける。監査ログには**内容を残さない**(長さだけ)。
- 触る場所: `sharing.py::validate_share`(許可する項目を増やす)、`ShareStore`(列を足す。**既存の DB の移行**を考える)、`engine.js`・`content.js`・`ui.js`。
- テスト: 上限超え・制御文字・他の利用者から見える範囲・**取り下げで消える**。
- 落とし穴: **既存の `shares.db` に列が無い**。`CREATE TABLE IF NOT EXISTS` だけでは、列は増えない(`ALTER TABLE` の扱い)。

## 演習 4: ダイジェストの重みを、利用者が選べるようにする(Python + JS)

**課題**: 情報量・代表性・導入の**重み**を、画面から変えられるようにする(「要点重視」「導入重視」)。

- 契約: 既定は今と同じ結果(**後方互換**)。重みの合計が 1 でなくても、点の**順序**だけが意味を持つ。
- 触る場所: `digest.py`・`core.js`(**両方**)・golden に新しいケース・`ui.js`・`content.js`。
- 手順: Python → golden → JavaScript([第 6 回](../lecture/06-python-js-parity.md))。
- 落とし穴: 重みを変えると、`score` の最大が 1 を超える(`min(1.0, …)` で丸めている)。

## 演習 5: 新しい字幕ソースを足す(ローカルファイル)

**課題**: 拡張でなく、**エンジンの CLI** で、ローカルの音声ファイル(自分の録音)から章を作る(`audio` コマンドの発展)。

- 契約: ファイルはこの PC のものだけ。**書き出さない**(区間データだけ)。長い音声は、**窓ごと**に処理してメモリを抑える。
- 触る場所: `cli.py::_cmd_audio`、`asr.py`。
- テスト: 合成の WAV(`tests/synth.py` に追加)で、境界の位置のずれを測る。
- 落とし穴: ASR は GPU を使うので、テストでは**偽の ASR**(`asr_fn`)を渡す。

## 自己採点の観点

- [ ] 契約を、実装の前に書いた(何を・誰が・どの範囲で)
- [ ] 守りのテスト(拒否されること)を足した
- [ ] 数値を決めたなら、**測って**(調整用と確認用を分けて)決めた
- [ ] 秘密を、ログ・文書・テストの出力に出していない
- [ ] 確認できていないことを、正直に書いた
