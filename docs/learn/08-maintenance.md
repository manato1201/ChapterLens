# 8. メンテナンス

文書とコードを**古くしない**ための決まりと、定期的にやることです。

## 8.1 いちばん壊れやすいもの: YouTube の画面

字幕(文字起こし)の取得は**非公式で変わりやすい**経路です。`transcript.js` に隔離してあります。

- 壊れたら、**理由つきのエラー**を出す(黙って誤った結果を出さない)。
- 直す場所は `transcript.js` の**セレクタだけ**。モックページ(`extension/tools/mock_server.mjs`)の DOM の作りも、本物に合わせて直す。
- 本物のページで確認するとき: 動画ページを開き、文字起こしの行の数・時刻が、画面と一致するか(`extension/README.md` の確認の手順)。
- ライブの判定(`isLiveVideo`)・進捗バーの目印(`.ytp-progress-bar`)も、YouTube の画面に依存する。**ライブで目印が出ない**のは仕様(再生位置の全体の長さが決まらない)。

## 8.3 評価データの扱い

- `engine/dataset/` は、**git に入れない・公開しない**(他人の字幕を含む)。`.gitignore` で除外してある。
- 追加するときは、**動画・音声を保存しない**。字幕・正解のチャプター・メタ情報だけ。
- **調整に使ったデータで、効果を測らない**(調整用 / 確認用を分ける)。データを足したら、必ず未見の分でも測る。
- 結果は `engine/results/`(git に入れない)。README に残すのは、**要約と、測り方**。

## 8.5 文書を古くしない

| 仕組み | 何を守るか |
|---|---|
| `# 引用:`(自動展開) | 講義に貼ったコードが、今のソースと一致する |
| `# 実行できる` + `# 出力` | 例が実際に動き、出力が書いてあるとおり |

| `make_diagrams.py` | 構成図は、コードで再現できる(手で描いた画像にしない) |
| `check_mermaid.py` | Mermaid の図が、実際に描画できる(構文の誤りが無い) |
| README の「確認の範囲」 | **測っていないこと・未確認のこと**を、そのまま書く |

**文書にも数値の出どころを書く**(「評価データ 39 本・2026-11-13」のように)。測り直したら、日付と本数を更新する。

## 8.6 方針を守る(やらないこと)

設計書 §13 の「やらないこと」を、変更のたびに思い出します。

- 動画・音声の**取得・保存・再配布**(他人の動画)。書き出しは自分の動画だけ(`--own`)。
- 全サイトでの動作(最初は YouTube だけ)。
- 要約記事の生成・翻訳・コメントの解析(**主な仕事ではない**)。
- 重みの再学習(最初は)。

機能を足すときは、**1 つ足すなら 1 つ外す**(設計書 R3)。足したら**測る**。

## 8.7 既知の限界(正直に)

- **拡張を本物の Chrome に読み込んでの動作**は、利用者の操作で確かめる段階(`tabCapture`・offscreen・popup)。
- **本物のライブ配信**での精度・遅れは未測定。音声認識の遅れは、そのまま「仮」「確定」の遅れに上乗せされる。
- **ダイジェストの「重要」**が、人の判断とどれだけ合うかは未測定(調整の一致率で測る道具はある)。
- 会話系(対談・ポッドキャスト)の検出精度は低い(F1 0.17〜0.24)。章は**候補**。
- token は `chrome.storage.local` に平文(設計書 S-B の OS の資格情報ストアには、まだ対応していない)。
- 認証は token だけで、失敗回数での締め出しは無い(256 ビットの乱数なので総当たりは非現実的)。

## 音声の取り込み経路の変更(2026-11-14)

実機で、`tabCapture` の経路が「Invalid capture constraints」「Error starting tab capture」で失敗した。**既定の経路を、動画ページの content script が `<video>.captureStream()` から音を取り出す方式に替えた**(popup は「始める合図」だけを送る)。

- content script が音を 16kHz・16bit・base64 にして、約 1 秒ごとに offscreen へ送り(`pcm`)、offscreen が 30 秒ずつ WAV にしてエンジン(127.0.0.1)へ送る。終わりは `pcm-end`。音は再生にそのまま流れ、ファイルには保存しない。
- `tabCapture` の経路(offscreen の `getUserMedia`)は、コードに残してあるが、popup からは使わない。権限(`tabCapture`)も、まだ manifest に残っている(外せるかは、実機で確かめてから)。
- 講義[第 7 回](../lecture/07-chrome-extension.md)・[第 8 回](../lecture/08-audio-and-asr.md)の `tabCapture` の説明は、この変更の前の記述。
- **未確認**: 本物の Chrome・YouTube での動作(Node のテストでは、`captureStream` を再現できない)。

## パネルの機能追加(2026-11-14)

- **パネルから音声を始める**: 「音声から作る」ボタン(接続設定は保存済みのものを background が使う。未設定のときだけ、設定画面を開く)。
- **エンジンの状態表示**: 読み取りだけの `GET /v1/health` を、中継の許可リストに足した(14 経路)。20 秒ごと・パネルが見えている間だけ。
- **題名の直接編集**(ダブルクリック)・**検索**(題名と字幕)・**一覧の自動スクロール**・**`[` / `]` キー**(前後の章)。
- **書き出し**: Markdown(クリップボードにもコピー)・字幕 SRT・VTT。
- **前回の結果**: 境界と題名(特徴語)を保存し、次に開いたとき、字幕を読む前に目次を出す。保存するのは、時刻・利用者が付けた題名・特徴語の題名まで(**字幕そのものと、代表の 1 文は保存しない**)。
- **未確認**: 本物の Chrome・YouTube での動作。
