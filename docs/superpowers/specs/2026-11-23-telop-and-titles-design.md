# テロップ表示と、題名・大見出しの改善(設計)

状態: **提案(承認待ち)**。2026-11-23。法律・性能の保証ではなく、設計の記録です。

## 1. なぜ作るか(意図)

- 長い配信アーカイブ(2 時間級)を、自分の画面で見ながら飛び回る。今の題名は「字幕のキーワードを並べたもの」で、**何をしている場面か**が読み取れない。
- 理想は、次のような形(本人が示した例)。
  - 章が**大見出し**で束ねられる(【釣りでお金かせぎ】)。
  - 章の題名が**1 行で具体的**(「魚を売る(6220ベル)」「血液型クイズ(正解はB型)」)。
  - 時刻にリンクが付く。
- 再生中に、**今の章の題名と大見出しを、動画の上に文字(テロップ)として重ねて表示**する。表示するのは**本人の画面だけ**。

## 2. 目的・非目的・避けたいこと

| 区分 | 内容 |
|---|---|
| 目的 | ①章の題名を具体的な 1 行にする ②章を大見出しで束ねる ③再生中のテロップ表示 ④コピー(概要欄・Markdown)に大見出しを入れる |
| 非目的 | 動画への焼き込み・書き出し(本人の動画は、既存の CH6 のまま)/画面の文字の読み取り(OCR)/Claude など外部への送信/テロップの見た目の細かな設定/モバイル |
| 避けたいこと(失敗) | ①字幕に無い**数字・固有名詞を作り話で入れる** ②字幕の本文が `127.0.0.1` の外へ出る ③題名付けの待ち時間で、基本の目次が出なくなる ④テロップが操作・字幕・広告の邪魔をする、点滅する |

## 3. 前提(確認した現状)

- 題名は拡張の `core.js`(`labelSections`)が、章ごとの TF-IDF の特徴語を並べて作る。要約はしない。大見出しの概念はない。
- `schema.py` の `TITLE_BY` には `llm` が既にあるが、LLM による題名付けは**未実装**(設計書 §4・決定 4: ローカル既定、有効化は管理者のみ、使った記録は監査ログ)。
- ローカル LLM は **LocalLLMHarness**(`http://127.0.0.1:8800/v1`、モデル `llh-main`=Qwen 3.5 9B、Unsloth Desktop)。**VRAM 8GB・1 度に 1 リクエスト・文脈 8192 トークン**。長い字幕は全文を渡せない。
- 拡張は、エンジン(127.0.0.1:8787)への中継を `background.js` の許可リストで行う(送り先は 127.0.0.1 だけ)。

## 4. 案と選択

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| **A(採用)** | 拡張 → **エンジン**(新 API)→ LocalLLMHarness | 設計書の決定 4(管理者の有効化・監査ログ・レート制限・字幕を「データ」として扱う S-D)に沿う。検証を Python で書け、既存の 339 件のテストの型で試せる。字幕だけの基本の目次は、エンジン無しのまま | 題名付けにはエンジンと窓口の起動が要る |
| B | 拡張 → 窓口へ直接 | 部品が少ない | 窓口の Origin 許可・token が拡張側に要る。監査ログ・検証が JS に分散。決定 4 から外れる |
| C | LLM なし(規則だけ改善) | 依存が増えない | 「魚を売る(6220ベル)」のような文は作れない |

→ **A** を採用(選んだのは私。本人は「ローカル LLM は Unsloth を使っている」とだけ指定)。C の規則は、LLM が使えない・検証に落ちたときの**代わりの題名**として残す。

## 5. 設計

### 5.1 題名・大見出しの作り方(エンジン)

境界の検出は、今のまま(拡張側)。LLM は**題名と見出しだけ**を作り、境界は動かさない。

1. **章ごとの題名**(`POST /v1/title`・1 章ずつ)
   - 入力: その章の字幕本文(長いときは、先頭・中ほど・末尾から均等に間引いて上限 約 4,000 文字)・前の章の題名(続きを判断する材料)。
   - 出力: 8〜24 文字の名詞句。必要なら末尾に(数字・結果)。
   - **検証(機械)**: 題名の中の数字(全角・半角・桁区切りを揃える)と固有名詞らしい語が、**その章の字幕に実在**すること。長さ上限・改行なし・空でないこと。落ちたら、落ちた理由を渡して 1 回だけ作り直し。それでも落ちたら**規則の題名に戻して**、`title_by=rule` のまま返す。
2. **大見出し**(`POST /v1/sections`・全章の題名の一覧を 1 回で)
   - 入力: `[{i, 題名}]` だけ(字幕本文は渡さない=短い)。
   - 出力: `[{heading, from, to}]`。**連続・昇順・全章を過不足なく覆う**こと(検証)。見出しは 16 文字以内。落ちたら 1 回作り直し、だめなら**大見出しなし**(平らな一覧)。
3. 1 章ずつ呼ぶので、**進捗が出せ、出来た順に画面へ反映**できる。窓口が直列化するので、エンジンも 1 度に 1 章。
4. 字幕は**データとして区切って**渡し、字幕中の指示には従わない(S-D)。
5. 設定: `[llm]`(既定は**無効**。有効化は管理者だけ)・`base_url`(loopback の http だけ)・`model`(既定 `llh-main`)・待ち時間。窓口の token は環境変数 `LLH_TOKEN` の**名前**で指定(値は設定ファイルに書かない)。
6. 監査ログ: 操作名・章数・モデル・秒数・検証に落ちた件数だけ。**字幕・題名・動画 ID は残さない**(既存の方針)。
7. 窓口が止まっている・モデルが未読み込みのときは、「`uv run llh serve` を起動してください」と分かる文を返し、**基本の目次はそのまま使える**。

### 5.2 データ

- 章: `{start, end, title, title_by: "rule"|"llm"|"user", section: <見出しの番号|null>}`。見出し: `{heading, from, to}`。
- 優先順位: 利用者が直した題名(`user`)> LLM(検証に通ったもの)> 規則。**利用者の直しは、再生成で上書きしない**。
- 結果は**動画ごとに、この PC のブラウザへ保存**(章の調整と同じ扱い)。次に開いたとき、LLM を呼ばずに出る。

### 5.3 画面(拡張)

- パネルに「題名を付ける(ローカル LLM)」を足す。エンジンに接続でき、LLM が有効なときだけ押せる。進行中は「12 / 48 章」を出し、**止められる**。
- 章の一覧に、大見出しを区切りとして出す。題名は出来た順に書き換わる。
- **テロップ**(下の表)。
- コピー(概要欄・Markdown)に、大見出しの行(`【…】`)を入れる。概要欄の形(先頭 0:00・3 つ以上・各 10 秒以上)は今のまま。

```
┌ 動画 ─────────────────────────┐
│          ┌──────────────────┐ │
│          │ 釣りでお金かせぎ    │ │ ← 大見出し(小さめ)。見出しが変わる章でだけ付く
│          │ 魚を売る(6220ベル)│ │ ← 章の題名(白地・黒の太字)
│          └──────────────────┘ │
└──────────────────────────────┘
```

| 項目 | 決め(私の案) |
|---|---|
| 置き場所 | プレイヤーの中(全画面でも見える)。右上。操作・字幕・進捗バーに重ならない |
| 出るとき | 章が変わった瞬間(シークで別の章に入ったときも)。約 4 秒で消える。1 回きりの動き(出現 0.2 秒・消える) |
| 切り替え | 「章の切り替えで出す(既定)/ 常に小さく出す / 出さない」。設定はブラウザに保存 |
| 邪魔をしない | クリックを通す(`pointer-events: none`)・広告中は出さない・`prefers-reduced-motion` では動かさず、透明度だけ・連続した章の変化は 0.5 秒まとめて 1 回 |
| 見た目 | 白地・黒の太字(本人の例のとおり)。大きさはプレイヤーの幅に合わせる。ライト・ダークの切り替えは不要(動画の上なので固定) |

## 6. 制約・安全

- 字幕の本文が行く先は、**この PC の エンジン と 窓口だけ**(どちらも 127.0.0.1)。外部へは出さない。
- 窓口は 8K トークン・直列。**1 章の入力を上限で切る**こと、章数が多いと**分単位**かかることが前提(5.1 の 3)。
- 題名は**要約であって事実の保証ではない**。数字・固有名詞は機械で字幕と突き合わせるが、字幕自体の誤認識は直せない。
- 他人の動画・音声・字幕は**保存・再配布しない**(設計書 §2)。保存するのは区間・題名・見出し・時刻だけ。

## 7. 確かめ方(受け入れ)

1. **機械で**: 偽の窓口(テスト用の小さなサーバー)で、題名の検証(作り話の数字を落とす・再試行・規則へ戻す)・見出しの検証(連続性・全章を覆う・不正なら見出しなし)・設定が無効のとき・窓口停止時・監査ログに本文が入らないこと・利用者の直しを上書きしないことを確認。拡張は、テロップの出る・出ない条件(切り替え・シーク・広告・reduced-motion)を単体で確認。
2. **実測(最初に行う)**: 実際の窓口で、実データ 5 章分の**1 章あたりの秒数**を測り、48 章でおよそ何分かを設計書に書く。**許容は本人が決める**(5 分未満なら標準、20 分超なら「題名を付ける」を、章数を絞る方式に変える)。
3. **本人の目で**: 例の動画(`r_1_4N7KiXo`)で、理想の例と比べて、題名・大見出しが使えるか(未確認の範囲として明記する)。

## 9. 私が決めたこと(本人が確認する)

- 案 A(エンジン経由)。LLM は題名と見出しだけで、境界は動かさない。
- LLM は既定で無効、押したときだけ動く。結果はブラウザに保存。
- テロップは右上・約 4 秒・白地黒の太字。常時表示は選択式。
- 検証に落ちた題名は規則の題名に戻す(作り話より、素朴な題名を選ぶ)。
